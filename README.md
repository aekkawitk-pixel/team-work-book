# สมุดคุมงานทีม (Team Work Book)

เว็บแอปสำหรับ **หัวหน้าแผนก** ใช้บันทึกงานที่รับเข้ามา มอบหมายงานให้ทีม ติดตามความคืบหน้า
และสร้างรายงานสรุปรายสัปดาห์ส่งผู้บริหาร

ผู้ใช้งานหลักคือหัวหน้าคนเดียว — ลูกน้องไม่ต้องล็อกอินและไม่ต้องกรอกข้อมูลเอง
UX จึงถูกออกแบบให้ **เพิ่มงานใหม่เสร็จภายใน 20 วินาที**

---

## เทคโนโลยี

| ส่วน | ใช้อะไร |
|---|---|
| Frontend | HTML + CSS + Vanilla JavaScript (ไม่มี framework, ไม่มี build step) |
| Backend | Supabase — Postgres + Auth (อีเมล/รหัสผ่าน) + Row Level Security |
| Hosting | Vercel (static) |

---

## โครงสร้างไฟล์

```
index.html            แอปพร้อมใช้ ไฟล์เดียวจบ (CSS + JS ฝังในตัว) — ไฟล์ที่ deploy จริง
src/shell.html        ซอร์ส HTML + CSS ที่อ่านง่าย
src/app.js            ซอร์ส JavaScript ที่อ่านง่าย (มีคอมเมนต์ภาษาไทย)
src/style.min.css     CSS ที่ผ่านการ minify แล้ว
supabase/schema.sql   สคีมาฐานข้อมูลทั้งหมด + RLS + trigger
vercel.json           ตั้งค่า Vercel
```

`index.html` สร้างจาก `src/` โดยรวม CSS เข้าไปใน `<style>` และ JS เข้าไปใน `<script>`
แก้ที่ `src/` แล้วประกอบใหม่ หรือจะแก้ที่ `index.html` ตรง ๆ ก็ได้

## 7 หน้าจอ

1. **วันนี้** — หน้าหลัก รวม “งานที่ต้องตาม” ที่ระบบจัดลำดับให้เอง
2. **งานทั้งหมด** — ค้นหา กรอง และอัปเดตงานได้จากรายการ
3. **ทีม** — ใครงานล้น ใครติดปัญหา ใครยังไม่ได้อัปเดต
4. **โครงการ** — ความคืบหน้ารายโครงการ
5. **สรุปสัปดาห์** — สร้างรายงานอัตโนมัติ คัดลอกส่ง LINE ได้ทันที
6. **พิมพ์รายงาน** — จัดหน้าเอกสารสำหรับพิมพ์หรือบันทึกเป็น PDF
7. **ตั้งค่า** — ทีม ผู้มอบหมายงาน โครงการ ค่าเริ่มต้น ธีม สำรองข้อมูล

## ระบบเตือนอัตโนมัติ (Smart Follow-up)

หน้า “วันนี้” รวมงานที่ต้องตามให้เอง โดยไม่ต้องตั้ง reminder เรียงตามความเร่งด่วน

| ลำดับ | เงื่อนไข |
|---|---|
| 1 | เลยกำหนดส่ง (`due_at < วันนี้`) |
| 2 | รอ / ติดปัญหา (`status = blocked`) |
| 3 | ถึงรอบรายงานแล้วยังไม่มีอัปเดต |
| 4 | ครบกำหนดวันนี้ |
| 5 | ครบกำหนดภายใน 2 วัน |
| 6 | ไม่มีการอัปเดตเกิน 4 วัน |

**รอบรายงาน** ตั้งได้ต่องาน — ทุกสัปดาห์ / ทุก 2 สัปดาห์ / ทุกเดือน
นับจากวันที่อัปเดตความคืบหน้าล่าสุด พอบันทึกอัปเดตใหม่ รอบจะรีเซ็ตทันที
และถ้าติ๊ก “สร้างงานรอบถัดไปอัตโนมัติ” พอปิดงานระบบจะสร้างงานของงวดถัดไปให้เลย

## ฐานข้อมูล

9 ตารางใน schema `public` ทุกตารางเปิด Row Level Security และผูกกับ `owner_id = auth.uid()`
แปลว่าผู้ใช้แต่ละคนเห็นเฉพาะข้อมูลของตัวเองเท่านั้น

```
settings              ตั้งค่าของผู้ใช้ (1 แถวต่อผู้ใช้)
members               รายชื่อทีม (รวมแถวของหัวหน้าเอง flag is_self)
requesters            ผู้มอบหมายงาน
projects              โครงการ
tasks                 งาน
task_collaborators    ผู้ร่วมงาน (many-to-many)
task_updates          ประวัติความคืบหน้า
notes                 บันทึกส่วนตัวของหัวหน้า
week_notes            แผน/ปัญหา รายสัปดาห์
```

ตอนสมัครสมาชิกครั้งแรก trigger `on_auth_user_created` จะสร้างแถว `settings`
และแถวสมาชิกของหัวหน้าให้อัตโนมัติ

สคีมาเต็มอยู่ที่ `supabase/schema.sql`

## ติดตั้งบนโปรเจกต์ Supabase ใหม่

1. สร้างโปรเจกต์ที่ [supabase.com](https://supabase.com)
2. เปิด SQL Editor แล้วรัน `supabase/schema.sql` ทั้งไฟล์
3. คัดลอก **Project URL** กับ **publishable key** จาก Settings → API
4. แก้ 2 ค่านี้ในไฟล์ที่ใช้งาน

```js
// ท้ายไฟล์ index.html (หรือ src/app.js)
window.supabase.createClient("<PROJECT_URL>", "<PUBLISHABLE_KEY>", ...)
```

publishable key เปิดเผยได้ตามการออกแบบของ Supabase — ความปลอดภัยมาจาก RLS ไม่ใช่จากการซ่อน key

## Deploy

**Vercel** — เชื่อม repo นี้แล้ว deploy ได้เลย ไม่ต้องตั้ง build command
(เป็น static site, output directory คือ root)

**ทางอื่น** — ไฟล์ `index.html` ทำงานได้ด้วยตัวเองทั้งไฟล์
ลากไปวางที่ Netlify Drop, วางบนเว็บเซิร์ฟเวอร์ใดก็ได้ หรือดับเบิลคลิกเปิดจากเครื่องตรง ๆ ก็ใช้ได้

## ข้อมูลสำรอง

หน้าตั้งค่ามีปุ่มดาวน์โหลด `.json` และปุ่มนำกลับเข้ามา
ตัวนำเข้ารองรับไฟล์สำรองจากเวอร์ชันก่อนหน้า (แบบ localStorage) ด้วย
โดยจะแปลง id เป็น UUID และย้ายขึ้นฐานข้อมูลให้อัตโนมัติ
